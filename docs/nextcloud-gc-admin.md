# Administrative retired-version collection

The data-source settings page has an administrator-only cleanup panel for the selected KB, including retired/withdrawn state, derived and recovery-copy expiry, estimated bytes, provider-confirmed released bytes, deferral reason, next retry, category/count preview, retry, and immediate collection attempt. Bounded pages use an exact tenant/KB-owned job cursor; 110 jobs were traversed without duplication or loss. Preview/status returns no storage path, URL, body or raw backend error. Employees do not receive the panel.

GET /datasource/nextcloud-gc-jobs supports knowledge_base_id and cursor. GET /datasource/nextcloud-gc-jobs/:id/preview gives category/count/expiry. POST /datasource/nextcloud-gc-jobs/:id/collect selects exactly that stored job; it accepts no locators or retention override. POST /datasource/nextcloud-gc-jobs/:id/retry requests the next sweep. API keys are refused, including full-access keys. Each request reloads the current web user and role. Mutations repeat current admin and KB edit policy through the transaction-bound authority factory; GC authorization selects only KB ownership columns, avoiding reads of retained templates.

Immediate collection repeats the existing source generation, current candidate, retention, references, complete coverage and read/build lease gates in the actual local SQL/provider transactions. It can complete a due item or report a blocker; it cannot activate production coverage, shorten the recovery window or turn an incomplete historical inventory into a complete one. Requested and finished audit rows separate acceptance from success/partial/failure and retain exact actor/scope/job metadata without object locators. SQL/native row removal is distinct from freeing allocated database pages.

Actual owned PostgreSQL and SQLite single-connection tests passed32 cases with no failures/skips. They include actual local unlink and confirmed bytes, retention refusal, absent coverage, active reader, disabled/demoted account, full API key, cross tenant, missing authority factory and revocation after provider preparation. HTTP denial hides inventory and the current role is reloaded from SQL. The first PG fixture failed its user→tenant FK because it omitted the tenant; that original log is retained and the fixture now creates the real owner tenant. The source was read-only and exact owned PG/network resources were removed. The frontend production bundle built, the actual app TypeScript project passed, and13 locale registry cases passed. See evidence/gc-admin-20261009.json.

The body purge module must integrate its selected-job stage into CollectJob after its own acceptance. Body cleanup, external graph/vector/object inventories and global reader/build coverage remain incomplete. No shared service was changed. This is candidate functionality, not completed V1 release acceptance.
