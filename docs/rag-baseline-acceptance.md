# RAG 检索基线验收记录（本地真实模型与合成题集已就绪）

此文件是可执行的验收模板。本地已接入真正的 BGE Embedding/ReRank，并用完全虚构的 16 题、16 段文档跑通独立检索烟测：在 12 道有答案题上，Embedding Recall@5=1.0、ReRank Recall@1=0.75、Recall@3/5=1.0、NDCG@5=1.0；热启动 P50≈120 ms、P95≈374 ms（单台 M2 Pro、MPS，小样本）。这只证明模型协议、维度及小样例检索可用，**不代表真实企业题集、WeKnora 端到端 RAG、答案忠实度或真实 AD 已通过**。完整验收仍须绑定提交、镜像 digest、已批准数据集指纹和模型版本；外发数据范围及费用须先经管理员批准。

## 准备

1. 可先用仓库自带的 `synthetic-zh-v1`（16 题）或 `synthetic-enterprise-zh-v2`（70 题）合成题集：`dataset/benchmarks/` 下已有各自的 5 个 Parquet 文件，生成方法与模型启动见 `scripts/local-rag-models/README.md`。后者虽模拟企业场景，**仍不是从企业数据脱敏或获得批准的真实题集**。真实题集请先按[企业脱敏题集交接清单](rag-enterprise-dataset-intake.md)取得数据负责人批准，在 `EVALUATION_DATASET_DIR/<dataset_id>/` 放置已脱敏文件并只读挂载给 app；不要将企业原文、AD 凭据或题集提交到 Git。
2. 本地模型为 `BAAI/bge-small-zh-v1.5`（512 维）和 `BAAI/bge-reranker-base`。确认正式部署所选版本、输入长度及服务地址；评估界面会拒绝名称含 `mock`/`test` 或维度不大于 3 的 Embedding。启动前以一条中文样本验证 Embedding、ReRank 返回有效结果。已有 3 维知识库必须新建或重建索引，不可直接复用。
   普通知识问答和知识搜索在未显式指定 ReRank 时使用可见的活动默认模型；租户默认优先于全局内置默认，智能体显式指定始终优先。重排会把问题及候选片段交给所选模型，管理员只能在确认数据发送范围后将外部模型设为默认；本机 BGE 是本地推理服务，不代表其他部署的默认模型也在本地。
3. 按“中文术语 / 跨文档组合 / 无答案 / 权限允许 / 权限拒绝”给题集分层。每题记录期望的证据段落 ID、参考答案或应拒答标记。权限题另列测试身份及其直接/嵌套 AD 组；现有离线评估 API **不执行** 身份切换，权限题须在真实登录会话下独立验证。离线评估走非流式 `rag` 流水线，不包含普通会话 `rag_stream` 的查询改写等阶段；不可把其时延与调用次数直接当作线上会话结果。
4. 记录外部模型发送范围：语料、问题、检索片段、提示词分别是否获准。临时知识库入库时的文档摘要也可能向所选对话模型发送整个题集；新运行在 `indexing_chat_model_id` 留下模型 ID，旧运行未记录该字段。未获准的数据只能用本地模型；不要用外部 LLM Judge 检查这些内容。

## 运行与记录

在「设置 → RAG Evaluation」选择数据集 ID、正式 Embedding、正式 ReRank 和对话模型。每次只改变一个变量，比较相同 `dataset_sha256` 的成功任务。任务详情与历史保存在数据库 `evaluation_runs`；重启后应能重新读取。记录如下表，原始运行 ID 保留供复核。

评估并发默认 2，可通过 `EVALUATION_MAX_CONCURRENCY` 设置为 1–64。任务记录实际并发数；版本对比只允许相同数据集指纹、指标口径版本和并发数的运行。指标口径 v2 的检索指标只对有证据标注的问题取平均，BLEU/ROUGE 只对有参考答案的问题取平均，界面显示各自的有效题数；无答案与权限拒绝题另行审核，不计为召回失败。旧版评估指标不可直接与 v2 对比。评估任务现以严格检索模式运行：查询 Embedding 失败、部分知识库检索失败或 ReRank API 失败会使任务失败，不再将关键词/原始排序降级结果标为正式基线；普通问答仍保留现有降级。正式运行仍须检查模型服务与应用日志中没有其他 `429` 或未覆盖的降级，任务成功本身不等于答案质量合格。

当前 API 持久化检索/生成聚合指标、P50/P95、token 数和逐题生成答案/证据 ID；**不自动计算引用准确率、证据忠实度或拒答正确率**。完成的任务可在界面逐题保存人工判定：有参考答案的题目分别给“证据忠实度”和“引用准确性”标为通过/失败；无答案题给“正确拒答”标为通过/失败。不适用项固定为“不适用”，未复核项不计入通过率。保存时记录登录管理员 ID、UTC 时间和修订历史，重启后仍从 `evaluation_runs` 读取；API Key 不允许提交人工标签。版本对比中的人工通过率只有在对应类别的**全部题目都已复核**后才显示，否则保留“—”，不能把部分标注误读为总体质量。忠实度可按“答案每个可核验断言均由给定证据支持；无支持断言记失败”标注；引用准确性需逐条确认引用指向相应证据。可参考 [RAGAS](https://arxiv.org/abs/2309.15217) 的 faithfulness/context relevance 和 [ARES](https://arxiv.org/abs/2311.09476) 的少量人工标注校准评审方法，但不能直接声称运行了这些框架。

可在完成的运行中另填版本化输入/输出 token 费率，保存具名管理员、时间、币种和修订历史；仅当新运行每条已记录的最终答复响应都回报用量时，界面计算并对比**最终答复对话 API 费用估算**。旧运行、零调用或部分缺失 token 时金额留空，不能按零计。固定拒答没有模型调用，不计入响应数；临时入库摘要、其他辅助 LLM 调用、最终响应之外的上游重试、Embedding、ReRank、本机算力、缓存价和税费均未计入，因此估算可能低于实际支出，也不是 RAG 总成本或供应商账单。正式成本验收还要取得价格表和这些遗漏项的独立记录。该价格快照功能不授权任何企业数据外发。

人工复核接口为 `PUT /api/v1/evaluation/{taskId}/cases/{questionId}/review`，仅接受已完成任务的同空间管理员会话；请求体只含 `faithfulness`、`citation_accuracy`、`abstention` 三个标签（`pass`、`fail`、`not_applicable`）。不得在评估数据库、复核记录或日志中粘贴企业原文；逐题问题、参考答案和生成答案本身会存入 `evaluation_runs`，因此该数据库必须按批准范围控制访问与保留期限。合成题集或确定性对话桩上的人工标签只能检验复核流程，不能用于企业效果签收。
